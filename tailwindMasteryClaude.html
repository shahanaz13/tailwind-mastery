Section 01
What is Tailwind CSS?
The mental model — utility-first CSS explained simply.
The Big Idea

Instead of writing CSS files, Tailwind gives you hundreds of tiny, single-purpose classes that are your CSS. Compose them directly in HTML.

❌ Traditional CSS 
/* style.css */
.card {
  background: white;
  padding: 24px;
  border-radius: 12px;
}
✅ Tailwind CSS 
<div class="bg-white p-6
  rounded-xl shadow-lg">
  Card content
</div>
💡Key insight: You never leave HTML. p-6 always means padding: 1.5rem. No surprises.
How Tailwind Works Internally
Your HTML / JSX
→
Tailwind Scanner
finds class names
→
JIT Engine
generates CSS
→
~5–15 KB
production file
Traditional vs Utility-First
Traditional CSS Tailwind CSS
HTML → separate CSS file Everything lives in HTML
Semantic names (.btn-primary) Classes describe behavior
CSS grows unboundedly CSS never grows — only used classes exist
Styles conflict across codebase Scoped to each element naturally
Afraid to delete CSS Safe to delete unused HTML

@layer base — Raw HTML Element Styles

  h1 { @apply text-3xl font-bold tracking-tight text-gray-900; }
  h2 { @apply text-2xl font-semibold text-gray-800; }
  a  { @apply text-blue-600 hover:underline; }
  p  { @apply leading-relaxed text-gray-600; }
  body { @apply antialiased; }
}
@layer components — Reusable Classes
@layer components {
  .btn {
    @apply inline-flex items-center justify-center px-4 py-2
           rounded-lg font-medium text-sm transition-all duration-200
           focus:outline-none focus:ring-2 focus:ring-offset-2
           disabled:opacity-50 disabled:cursor-not-allowed;
  }
  .btn-primary { @apply btn bg-blue-600 text-white hover:bg-blue-700 active:scale-95 focus:ring-blue-500; }
  .btn-outline  { @apply btn border border-gray-300 text-gray-700 hover:bg-gray-50; }
  .btn-ghost    { @apply btn text-gray-600 hover:bg-gray-100; }

  .input {
    @apply w-full border border-gray-300 rounded-lg px-3 py-2 text-sm
           placeholder:text-gray-400
           focus:outline-none focus:ring-2 focus:ring-blue-500 focus:border-transparent transition;
  }
  .card  { @apply bg-white rounded-2xl shadow-sm border border-gray-100 p-6; }
  .badge { @apply inline-flex items-center px-2.5 py-0.5 rounded-full text-xs font-medium; }
  .badge-green  { @apply badge bg-green-100 text-green-800; }
  .badge-red    { @apply badge bg-red-100 text-red-800; }
}
⚠️ Don't overuse @apply — use it only for truly repeated primitives like .btn and .input.

Section 15
Tailwind in React & Next.js Advanced
Best practices and tools the pros actually use.
clsx + tailwind-merge — The Essential Combo 
npm install clsx tailwind-merge
// lib/utils.js — the cn() helper (shadcn/ui pattern)
import { clsx } from 'clsx'
import { twMerge } from 'tailwind-merge'

export function cn(...inputs) {
  return twMerge(clsx(inputs))
}
// Usage in a component
import { cn } from '@/lib/utils'

function Button({ variant, disabled, className, children }) {
  return (
    <button className={cn(
      'px-4 py-2 rounded-lg font-medium transition-all',
      variant === 'primary' && 'bg-blue-600 text-white hover:bg-blue-700',
      variant === 'ghost'   && 'text-gray-600 hover:bg-gray-100',
      variant === 'danger'  && 'bg-red-600 text-white hover:bg-red-700',
      disabled && 'opacity-50 cursor-not-allowed',
      className   // allows parent to override
    )}>{children}</button>
  )
}
💡 Why tailwind-merge? If parent passes p-4 and component has p-6, twMerge picks the last one — no conflicting duplicates.
CVA — Class Variance Authority
npm install class-variance-authority
import { cva } from 'class-variance-authority'
import { cn } from '@/lib/utils'

const buttonVariants = cva(
  'inline-flex items-center justify-center rounded-lg font-medium transition-all
   focus-visible:ring-2 disabled:pointer-events-none disabled:opacity-50',
  {
    variants: {
      variant: {
        default:  'bg-blue-600 text-white hover:bg-blue-700',
        outline:  'border border-gray-300 bg-white hover:bg-gray-50 text-gray-900',
        ghost:    'hover:bg-gray-100 text-gray-900',
        danger:   'bg-red-600 text-white hover:bg-red-700',
      },
      size: {
        sm:      'h-8 px-3 text-xs',
        default: 'h-10 px-4 py-2 text-sm',
        lg:      'h-12 px-8 text-base',
        icon:    'h-10 w-10',
      },
    },
    defaultVariants: { variant: 'default', size: 'default' },
  }
)

function Button({ variant, size, className, ...props }) {
  return <button className={cn(buttonVariants({ variant, size }), className)} {...props}/>
}

// Usage:
<Button variant="outline" size="lg">Click me</Button>
<Button variant="danger">Delete</Button>
⚠️ The #1 Gotcha — Dynamic Class Strings
❌ BROKEN 
// Tailwind can't scan this at build time!
const color = 'blue'
<div className={`bg-${color}-500`}>
✅ CORRECT 
const map = {
  blue:  'bg-blue-500',
  red:   'bg-red-500',
  green: 'bg-green-500',
}
<div className={map[color]}>
ℹ️ Tailwind scans source files for complete class strings. It cannot parse template literals. Always write full, complete class names.

Performance Tips Advanced
Keep your CSS tiny and builds fast.
How JIT Purging Works
Source files

→

CSS Generator
only used classes

Best Practices vs Common Mistakes
Do This ✅ Avoid This ❌
Full class strings: bg-blue-500 Template literals: bg-${color}-500
Use gap- for flex/grid spacing Adding margin to every individual child
Custom values in theme.extend Arbitrary values everywhere: mt-[127px]
transition-colors not transition-all transition-all (triggers layout recalc)
will-change-transform on animated items Animating layout properties (width/height)
@apply sparingly for true reuse @apply for everything
Content Paths & Safelist
// tailwind.config.js — cover ALL file types
content: [
  './src/**/*.{html,js,jsx,ts,tsx,vue,svelte}',
  './node_modules/@your-ui-lib/**/*.{js,jsx}',
]

// Safelist — force-include dynamic classes
safelist: [
  'bg-blue-500', 'bg-red-500', 'bg-green-500',
  { pattern: /bg-(red|blue|green)-(100|500|900)/ },
  { pattern: /text-(sm|base|lg)/, variants: ['hover', 'md'] },
]

Section 20
Common Mistakes & Fixes
The 7 mistakes everyone makes — and exactly how to fix them.
Mistake 1 — Dynamic Class Strings
❌ Broken — class never generated 
// Tailwind scans source at build time
// It cannot evaluate this at runtime!
const color = 'blue'
<div className={`bg-${color}-500`}>
✅ Fixed — full strings in source 
const colorMap = {
  blue:  'bg-blue-500',
  red:   'bg-red-500',
  green: 'bg-green-500',
}
<div className={colorMap[color]}>
ℹ️ Tailwind needs complete class strings present in your source files at build time. Template literals are evaluated at runtime — Tailwind never sees them.
Mistake 2 — Misunderstanding Mobile-First
❌ Wrong mental model 
// Thinking md: means "only on md"
// This does NOT work as expected
hidden md:block lg:hidden
// ← shows on md AND lg, not just md
✅ Correct — no prefix = all, prefix = up 
// No prefix = ALL screen sizes
// md: = 768px and UPWARD forever

hidden md:block
// hidden on mobile, visible md+

block md:hidden
// visible on mobile, hidden md+
Mistake 3 — Overusing @apply
❌ Defeats the whole purpose 
/* You're back to writing CSS for everything */
.page-wrapper {
  @apply flex flex-col min-h-screen;
}
.section-title {
  @apply text-3xl font-bold;
}
.hero-text {
  @apply text-gray-600 leading-relaxed;
}
✅ Just write it in HTML 
<div class="flex flex-col min-h-screen">
  <h1 class="text-3xl font-bold">Title</h1>
  <p class="text-gray-600 leading-relaxed">
    Text
  </p>

/* @apply only for true primitives */
.btn-primary { @apply ... }
.input       { @apply ... }
💡 Use @apply only for truly repeated UI primitives that appear dozens of times: .btn, .input, .badge.
Mistake 4 — Wrong Content Paths (Prod Bug)
❌ Too narrow — misses files 
content: [
  './src/**/*.html'
  // misses .jsx .tsx .vue .svelte!
]
✅ Cover every file that has classes 
content: [
  './src/**/*.{html,js,jsx,ts,tsx}',
  // include UI library if it uses classes:
  './node_modules/@ui-lib/**/*.{js,jsx}',
]
⚠️ "Works in dev, broken in prod" is almost always a missing content path. This is the #1 production bug with Tailwind.
Mistake 5 — Margin on Every Child Instead of Gap
❌ Fragile — last child gets extra margin 
<div class="flex">
  <div class="mr-4">Item 1</div>
  <div class="mr-4">Item 2</div>
  <div>Item 3</div> ← inconsistent!
</div>
✅ Clean — gap handles everything 
<div class="flex gap-4">
  <div>Item 1</div>
  <div>Item 2</div>
  <div>Item 3</div>
</div>
Mistake 6 — Using transition-all
❌ Triggers layout recalculation 
/* transitions EVERYTHING including */
/* width, height — causes jank */
transition-all duration-300
✅ Only transition what changes 
/* hover color change */
transition-colors duration-200

/* hover scale/move */
transition-transform duration-200

/* fade in/out */
transition-opacity duration-200
Mistake 7 — Replacing Instead of Extending Theme
❌ Replaces ALL default colors 
// tailwind.config.js
theme: {
  colors: {
    brand: '#6366f1'
    // ALL default colors gone!
    // No more blue, red, gray...
  }
}
✅ extend keeps defaults + adds yours 
// tailwind.config.js
theme: {
  extend: {
    colors: {
      brand: '#6366f1'
      // All Tailwind colors still work ✓
    }
  }
}
⚠️ Always use theme.extend unless you intentionally want to replace the entire default theme.
